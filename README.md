# 📚 Deadline Bot

Telegram-бот для уведомления студентов о дедлайнах лабораторных работ.  
Написан на Go, хранит данные в SQLite, разворачивается через Docker Compose.

## 1. Быстрый старт через Docker

### Предварительные требования

| Инструмент | Минимальная версия |
|---|---|
| Docker | 24+ |
| Docker Compose | v2 |

### Шаги

```bash
# 1. Клонировать репозиторий
git clone https://github.com/your-org/deadline_bot.git
cd deadline_bot

# 2. Создать файл с переменными окружения
cp .env.example .env
# Указать токен, публичный HTTPS URL и секрет webhook в .env
nano .env

# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить логи
docker compose logs -f
```

> [!IMPORTANT]
> Перед запуском обязательно заполните `TELEGRAM_TOKEN` и `OWNER_TELEGRAM_ID` в файле `.env`.

Перед запуском укажите домен, который уже направлен на сервер, и настройте HTTPS reverse proxy до порта `8080` контейнера. Например, Caddy автоматически выпустит TLS-сертификат:

```caddyfile
bot.example.com {
  reverse_proxy localhost:8080
}
```

Путь из `WEBHOOK_URL` должен передаваться без изменений. Секрет можно сгенерировать командой `openssl rand -hex 32`. Откройте входящий порт reverse proxy для Telegram; сам процесс бота принимает обычный HTTP только за прокси.

После успешного старта вы увидите в логах:
```
INFO Database migrations completed successfully
INFO Telegram webhook started bot_username=...
```

## 2. Локальный запуск без Docker

### Требования

- Go 1.27.1+
- SQLite (чистый Go-драйвер, CGO **не нужен**)

### Шаги

```bash
# Установить зависимости
go mod download

# Создать файл окружения
cp .env.example .env
nano .env  # заполнить Telegram token, WEBHOOK_URL, WEBHOOK_SECRET_TOKEN и OWNER_TELEGRAM_ID

# Создать директорию для БД
mkdir -p data

# Запустить
go run ./cmd/bot
```

Или собрать бинарник и запустить его:

```bash
go build -o deadline_bot ./cmd/bot
./deadline_bot
```

## 3. Переменные окружения

Все переменные задаются в файле `.env` (при запуске через Docker Compose) или экспортируются в шелл (при локальном запуске).

| Переменная | Обязательная | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | — | Токен бота от @BotFather (`TELEGRAM_TOKEN` поддерживается как старый alias) |
| `WEBHOOK_URL` | ✅ | — | Публичный HTTPS URL webhook, включая секретный путь |
| `WEBHOOK_SECRET_TOKEN` | ✅ | — | Секрет для проверки заголовка Telegram webhook |
| `WEBHOOK_LISTEN_ADDR` | ❌ | `:8080` | HTTP-адрес, на котором бот принимает webhook за TLS reverse proxy |
| `WEBHOOK_PORT` | ❌ | `8080` | Порт хоста, опубликованный Docker Compose |
| `OWNER_TELEGRAM_ID` | ✅ | — | Telegram User ID владельца (получить через @userinfobot) |
| `DATABASE_PATH` | ✅ | — | Путь к файлу SQLite (`./data/bot.db` или `/data/bot.db` в Docker) |
| `TURSO_DATABASE_URL` | ❌ | — | URL постоянной Turso/libSQL базы; при наличии используется вместо `DATABASE_PATH` |
| `TURSO_AUTH_TOKEN` | при Turso | — | Секретный токен доступа к Turso; хранить только в переменных окружения |
| `GROUP_TIMEZONE` | ❌ | `Europe/Minsk` | IANA-часовой пояс для дедлайнов и напоминаний (`TIMEZONE` поддерживается как старый alias) |
| `NOTIFICATION_CHECK_INTERVAL` | ❌ | `1m` | Интервал проверки БД воркером уведомлений (`NOTIFICATION_POLL_SECONDS` поддерживается как старый alias) |
| `LOG_LEVEL` | ❌ | `info` | Уровень логирования: `debug`, `info`, `warn`, `error` |

> [!NOTE]
> Файл `.env` никогда не должен попадать в Git. Добавьте его в `.gitignore` (он уже там).

### Постоянная база на бесплатном Render

Локальный SQLite-файл на бесплатном Render удаляется после сна или перезапуска сервиса. Для постоянного хранения создайте Turso-базу и задайте в Render Environment:

```dotenv
TURSO_DATABASE_URL=libsql://your-database.turso.io
TURSO_AUTH_TOKEN=your-secret-token
```

Не добавляйте токен Turso в `.env.example` или Git. При наличии этих переменных приложение автоматически использует Turso вместо `DATABASE_PATH`.

## 4. Первоначальная настройка бота (через Telegram)

### 4.1 Создание бота у @BotFather

1. Открыть чат с **@BotFather** в Telegram.
2. Отправить `/newbot`.
3. Указать имя и username бота (например, `@MyGroupDeadlineBot`).
4. Скопировать полученный **токен** и вставить в `.env` в поле `TELEGRAM_BOT_TOKEN`.

### 4.2 Узнать свой Telegram ID

1. Найти бота **@userinfobot** в Telegram и написать ему любое сообщение.
2. Скопировать `Id` из ответа и вставить в `.env` в поле `OWNER_TELEGRAM_ID`.

### 4.3 Первый запуск и настройка группы

После запуска бота:

1. Откройте чат с ботом и отправьте `/start`.
2. **Владелец** (чей Telegram ID задан в `OWNER_TELEGRAM_ID`) увидит меню владельца без ввода кода приглашения.
3. Перейдите в раздел **«Настройки группы»** → **«Настроить группу»**.
4. Введите название учебной группы (например, `ИВТ-21`).
5. Задайте **код приглашения** — любую строку, которую вы сообщите студентам (например, `ivt21-2024`).

### 4.4 Подключение студентов

1. Студент открывает чат с ботом и отправляет `/start`.
2. Бот запрашивает код приглашения.
3. Студент вводит код, который сообщил ему администратор.
4. При правильном коде студент подключается к группе и видит главное меню.

> [!NOTE]
> Если студент уже был подключён ранее и снова нажимает `/start`, дубликат пользователя не создаётся.

### 4.5 Назначение администраторов (старосты, заместителя)

В меню владельца: **«Управление пользователями»** → выбрать пользователя → **«Сделать администратором»**.

Администратор получает возможность:
- создавать, редактировать и отменять лабораторные работы;
- управлять предметами;
- менять код приглашения.

### 4.6 Создание первого предмета и лабораторной

1. Администратор открывает **«Управление предметами»** → **«Добавить предмет»** → вводит название.
2. Затем **«Управление лабораторными»** → **«Добавить лабораторную»** — следует пошаговый диалог:
   - выбор предмета;
   - номер и название работы;
   - описание (опционально, кнопка «Пропустить»);
   - дата и время сдачи (формат `ДД.ММ.ГГГГ` или `ДД.ММ.ГГГГ ЧЧ:ММ`; если время не указано, предлагается 23:59);
   - ссылка (опционально);
   - файл (опционально);
   - способ сдачи и комментарий преподавателя (опционально);
   - предварительный просмотр карточки и подтверждение.

## 5. Роли и права доступа

| Роль | Возможности |
|---|---|
| **Студент** | Просмотр дедлайнов, настройка уведомлений, личная отметка «Сдано» |
| **Администратор** | Всё выше + управление предметами и лабораторными, управление кодом приглашения, отзыв доступа студентов |
| **Владелец** | Всё выше + назначение/удаление администраторов, первоначальная настройка группы |

> [!IMPORTANT]
> Отметка «Сдано» является личной и не подтверждает сдачу преподавателю.  
> Студент не может менять статусы других студентов.

После **отзыва доступа** (через меню администратора) пользователь перестаёт получать уведомления и видеть данные группы.

## 7. Миграции базы данных

Миграции применяются **автоматически при каждом запуске** бота, до старта обработчиков и воркера.

- Файлы миграций находятся в директории `migrations/` и встраиваются в бинарник через `//go:embed`.
- Уже применённые миграции не повторяются (таблица `schema_migrations`).
- Если миграция завершается с ошибкой, приложение останавливается с диагностическим сообщением в логе.

Добавить новую миграцию:

```bash
# Создать файл с порядковым номером
touch migrations/002_add_column.sql
# Написать SQL
# Перезапустить бот — миграция применится автоматически
```

## 8. Резервное копирование и восстановление SQLite

### Резервная копия (онлайн, без остановки бота)

```bash
# Через Docker (безопасная горячая копия через SQLite VACUUM INTO)
docker compose exec bot sh -c \
  'sqlite3 /data/bot.db "VACUUM INTO '\''/data/bot_backup_$(date +%Y%m%d_%H%M%S).db'\''"'

# Или просто скопировать файл тома на хост
docker compose cp bot:/data/bot.db ./backup/bot.db
```

> [!TIP]
> Используйте `VACUUM INTO` вместо простого копирования — это единственный способ получить консистентную копию без остановки процесса.

### Восстановление

```bash
# 1. Остановить бот
docker compose stop bot

# 2. Скопировать резервную копию в том
docker compose cp ./backup/bot.db bot:/data/bot.db

# 3. Запустить бот
docker compose start bot
```

### Автоматические резервные копии (cron-пример)

```cron
# Ежедневно в 03:00 — горячая копия
0 3 * * * docker compose -f /srv/deadline_bot/docker-compose.yml exec -T bot \
  sqlite3 /data/bot.db "VACUUM INTO '/data/backup_$(date +\%Y\%m\%d).db'" \
  >> /var/log/deadline_bot_backup.log 2>&1
```

## 9. Остановка и обновление

```bash
# Остановить бот
docker compose stop

# Пересобрать образ и перезапустить (данные в volume сохраняются)
git pull
docker compose up -d --build

# Просмотр логов в реальном времени
docker compose logs -f bot

# Полная очистка (УДАЛЯЕТ данные!)
docker compose down -v
```

> [!CAUTION]
> `docker compose down -v` удаляет именованный volume `bot_data` вместе с базой данных.  
> Перед этой командой обязательно сделайте резервную копию.
